1. Website Overview

The Asian Dental Clinic website is a fully responsive dental clinic portal built for Asian Dental Clinic & Implant Center, Hoskote, Bengaluru. It serves three types of users:

🧑‍⚕️

Patients (Public)

Browse services, view gallery, read reviews, and book consultations online.

👨‍⚕️

Doctors

View patient enquiries, appointments, and assign cases to admin staff.

🛡️

Admin Staff

Call patients, confirm/reject appointments, send WhatsApp notifications.

☁️

Cloud Database

All enquiries and appointments stored securely in Supabase (PostgreSQL).

Website URL (Production) Hosted on Netlify — deploy from GitHub repository: rkvelpsg-cyber/teethcaredentalbangalore

3. Book a Consultation – Enquiry Form

Patients can click the "Book Consultation" or "Book Appointment" button anywhere on the website to open the enquiry pop-up form.

How the Form Works

1
Patient fills in the form Fields: Full Name, Phone Number, Email Address, Message (optional)
2
Click "Send Enquiry" WhatsApp opens automatically to clinic number +91-9663252315 with patient details pre-filled
3
Data saved to cloud database Patient details are saved to Supabase (online_enquiries table) in real time
4
Doctor receives the enquiry The enquiry appears in Dr. Humayun's Doctor Dashboard under "Online Enquiry"
💡 Note The "Book a Consultation" pop-up does NOT appear automatically when the page loads. It only opens when the patient clicks a button — this was intentionally configured.

Doctor Dashboard Sections

📊 Dashboard (Home)

Shows 4 live statistics pulled from the database:

  • Total Enquiries — all online enquiries received
  • Pending Enquiries — enquiries with no action yet

📅 Appointments

  • Shows all confirmed appointments from the database
  • Date range filter — filter by start and end date
  • Export to Excel — download appointment data as .xlsx file

📬 Online Enquiry

  • Shows all patient enquiries submitted via the website form

  • Date range filter + Export to Excel available

✅ Primary Doctor Dr. Humayun Aleem is the primary doctor. All online enquiries from patients are first visible in his dashboard. He reviews them and assigns them to the Admin Staff for calling and confirmation.

6. End-to-End Appointment Workflow

This is the complete journey from a patient's enquiry to a confirmed appointment:

1
Patient Submits enquiry online Patient fills "Book a Consultation" form on the website → WhatsApp opens + data saved to Supabase
2
Doctor Reviews enquiry in dashboard Dr. Humayun logs in → sees new enquiry badge → opens "Online Enquiry" section
3
Doctor Assigns to Admin Clicks "Assign Admin" button → enquiry moves to admin's dashboard with status "Responded"
4
Admin Calls the patient Admin logs in → opens "Assigned Enquiries" → calls patient's phone number shown in the table
5
Admin Updates appointment status Clicks "Update" → sets appointment date, time, notes → clicks "Confirm Appointment" or "Not Confirmed"
6
Admin Sends WhatsApp confirmation WhatsApp opens automatically to patient's number with appointment details pre-filled in the message
7
Doctor Sees confirmed appointments Confirmed appointments appear in doctor's "Appointments" section with all details
📱 WhatsApp Notification The clinic's WhatsApp number (+91-9663252315) must be active on the admin's device for the WhatsApp confirmation message to be sent from the clinic's number. The message is pre-filled with the patient's name, appointment date and time.

8. Support & Troubleshooting

Common Issues

❌ WhatsApp pop-up blocked

The browser is blocking the WhatsApp tab from opening. Go to browser Settings → allow pop-ups for this website, then try again.

❌ "Assign Admin" showing error

The Supabase database may be missing the new columns. Run the migration SQL from supabase-schema.sql in the Supabase SQL Editor.

❌ Login not working

Ensure the Supabase project is active and the doctors / admins tables have the correct records. Verify the password matches what was set in the SQL INSERT statement.

❌ Enquiries not appearing in dashboard

Check that the RLS (Row Level Security) policies are applied in Supabase. Re-run the policy section of supabase-schema.sql.
